# CS144 Unit 1 — Internet 架构

### 1.1 A day in the life of an application
- **字节流模型 (Byte Stream)**：应用通过 **Socket** 将数据视为连续字节流，由传输层处理分段与重传，对应用层呈现透明通道。
- **三种应用的架构与特性区别**：
  1. **HTTP (Client-Server)**：经典的**中心化**模型。客户端请求，服务器响应。高度依赖服务器性能，扩展性受限于单点（或负载均衡）。
  2. **BitTorrent (P2P)**：**去中心化**的分块分发。数据不在一个地方，而是从成千上万个「对等点」并行下载。**人越多，下载越快**，彻底解决了中心带宽瓶颈。
  3. **Skype (Interactive)**：**实时交互**。对时延（Latency）极度敏感，宁可丢包也不能等待重传。核心难点在于**NAT 穿透**，通过超级节点（Supernodes）让内网的两个终端直接通话。
- **总结**：应用根据**可靠性、扩展性、实时性**的权衡，选择不同的网络交互模式。

### 1.2 The four layer Internet model
- **链路层 (Link)**：负责物理相邻节点间的包传递（如 WiFi, Ethernet）。
- **网络层 (Network/IP)**：**最核心，最薄**。实现全球范围内的端到端连接，定义了所有节点的通用语言（IP 包）。
- **传输层 (Transport)**：在端系统间提供通信服务（TCP 提供可靠流，UDP 提供原始数据报）。
- **应用层 (Application)**：各种网络应用协议（HTTP, DNS, gRPC）。

### 1.3 The IP service model
- **尽力而为 (Best-effort)**：不保证送达，不保证顺序，不保证时延。
- **简单化**：将复杂性（重传、流控）推向网络边缘（端系统），保持网络核心（IP 层）极其精简。

### 1.4 A Day in the Life of a Packet
- **建立连接**：通过 **TCP 三次握手**（SYN, SYN-ACK, ACK）在端系统间同步状态。
- **逐跳处理 (Inside each hop)**：
  1. **解封装**：从链路层剥离，读取 IP 头部。
  2. **查表转发**：根据目的 IP 查路由表（最长前缀匹配）。
  3. **头部更新**：递减 TTL，重新计算 Checksum。
  4. **重新封装**：封装进下一跳的链路层帧并发出。
- **端到端传输**：数据包跨越多个异构网络，由每跳路由器独立完成局部路由决策。

### 1.5 Principle: Packet Switching
**核心优势**
- **简单 (Simple)**：中间节点（路由器）**无状态**，不维护连接信息，仅需独立转发每个包。
- **高效 (Efficient)**：通过 **统计复用** 动态共享带宽，极大提升了突发流量下的链路利用率。

**转发模型**
- **Store-and-forward**：整包接收后再转发。
- **Destination routing**：仅带目的地址，每跳独立查表。
- **Source routing**：发送端指定路径（废弃）。

**代价**：不保证带宽，可能排队/丢包；可靠性由端系统（TCP）负责。

### 1.6 Principle: Layering (分层)
**分层原因**
1. **模块化 (Modularization)**：将复杂系统拆解为易管理的模块。
2. **定义明确的服务 (Well-defined service)**：层间接口清晰，隐藏实现细节。
3. **复用性 (Reuse)**：上层可共享下层提供的标准服务。
4. **关注点分离 (Separation of concerns)**：每层只解决特定维度的通信问题。
5. **持续演进 (Continuous improvement)**：各层可独立迭代优化，互不干扰。

**一句话总结**：以模块化解耦复杂性，平衡通用性与演进速度。

### 1.7 Principle: Encapsulation (封装原则)
- **核心**：上层数据被视为下层的 **Payload (有效负载)**。
- **VPN 隧道 (以 SSL/TLS VPN 封装可以递归的)**：
  - **结构**：`[外层 IP][外层 TCP/UDP][TLS][内层 IP][内层 TCP][Data]`
  - **TLS 的角色**：在应用层与传输层之间建立加密管道，保护封装在内的整个「私网 IP 包」。
  - **分层灵活性**：
    - **嵌套**：证明了可以在应用层（TLS）中跑网络层（IP）。
    - **伪装**：通过 TLS 封装，VPN 流量可以伪装成普通 HTTPS 流量绕过防火墙。
  - **结论**：每一层只需关注如何处理其 Payload，而不必关心 Payload 内部是否又是一个完整的协议栈。

### 1.8 Byte Order (字节序)
- **大端序 (Big-endian)**：高位字节存放在低地址（人类直觉顺序）。
- **小端序 (Little-endian)**：低位字节存放在低地址（x86 架构常用）。
- **网络字节序**：计算机网络协议规定一律使用 **大端序 (Big-endian)**。
- **举例：IP 头部 Total Length (16位)**
  - 长度为 1500 (十六进制 `0x05DC`)。
  - **网络传输顺序**：先传 `05`，再传 `DC`。
  - **小端序主机内存存储**：`DC` 在前，`05` 在后。主机发送前需进行字节序转换（如 `htons()`）。
- **目的**：确保异构系统（不同 CPU 架构）对多字节字段的解析达成一致。

### 1.9 IPv4 地址与子网划分
- **IPv4**：32 位二进制地址。
- **子网掩码 (Subnet Mask)**：通过 **按位与 (AND)** 运算区分网络号与主机号。
- **CIDR (无类域间路由)**：`IP/n` 格式（如 `/24` 代表前 24 位为网络号），支持灵活划分与路由聚合。
- **转发决策 (Key)**：
  - **公式**：`(Source_IP & Mask) == (Dest_IP & Mask)`
  - **相等**：同子网，二层直接交付（ARP + MAC）。
  - **不等**：异子网，发往 **默认网关 (Default Gateway)**，经 NAT 访问外网。
- **地址分发 & NAT**：
  - **DHCP**：终端通过广播发现服务器，动态租借 IP。
  - **私有地址**：`10.x`, `192.168.x` 等网段，配合 NAT 实现多设备共享一个公网 IP。
  - **IP 不一致现象**：内网 IP (如 `10.43.26.164`) 是局域网分机号；查询 IP (如 `43.132.141.20`) 是公网总机号。
  - **CGNAT (大内网)**：若路由器 WAN 口为私网 IP 而非公网 IP，则与邻居共用公网出口。
- **特殊地址**：网络地址 (全 0)、广播地址 (全 1)、Loopback (`127.0.0.1`)。

**实战举例 (基于本机配置)**：
- **本机 IP**: `10.43.26.164` (CIDR: `10.43.26.164/24`)
- **掩码**: `255.255.255.0` -> 前 24 位为网络号 `10.43.26`。
- **默认网关**: `10.43.26.1` -> 出小区的「大门」。
- **逻辑**: 访问 `10.43.26.50` 时运算结果匹配，直接内网传输；访问 `8.8.8.8` 时结果不匹配，包被扔给 `10.43.26.1` 处理。

### 1.10 Longest Prefix Match (最长前缀匹配)
- **定义**：当一个目的 IP 同时匹配多条路由条目时，路由器优先选择 **掩码长度最长**（最精确）的那条记录。
- **核心逻辑**：
  - **二进制匹配**：必须从第一位开始，每一位都与条目前缀完全一致，直到达到掩码规定的位数。差一位即视为不匹配。
  - **优先级**：`/24` 优于 `/16`，`/16` 优于 `/8`，`/0` (默认路由) 最低。
- **设计目的**：
  - **路由聚合**：允许将大量连续 IP 聚合为一条短前缀记录，缩减全球路由表规模。
  - **例外处理**：在大网段覆盖范围内，允许为特定子网定义「特例」路径。
- **举例**：目标 `10.43.26.164` 同时命中 `10.0.0.0/8` 和 `10.43.26.0/24`，路由器最终选择 `/24` 条目对应的接口发出。

### 1.11 ARP (Address Resolution Protocol)
- **作用**：**已知目标 IP，求解其 MAC 地址**。是网络层与链路层之间的「胶水」。
- **工作流程**：
  1. **ARP Request**：向局域网广播（目的 MAC 为全 `F`）询问特定 IP 的拥有者。
  2. **ARP Reply**：目标主机以单播方式响应自己的 MAC 地址。
  3. **ARP Cache**：本机缓存结果以便后续复用（查看命令：`arp -a`）。
- **关键规则**：
  - **范围**：仅在本地局域网（L2）生效。
  - **外网访问**：若目标不在同子网，主机求得的是 **默认网关** 的 MAC 地址，将包交给网关转发。
- **安全性**：**ARP 欺骗**。由于缺乏验证机制，黑客可伪造回复将流量引向自己。
- **对比**：DNS（域名 -> IP，全球范围）；ARP（IP -> MAC，局域网范围）。

### 1.12 总结 The Internet and IP recap
- **应用如何使用互联网**：经 Socket 把数据交给传输层；HTTP 走 C/S，BitTorrent 走 P2P，Skype 走实时交互。
- **四层模型**：应用 → 传输（TCP/UDP）→ 网络（IP）→ 链路。层间封装，各层只处理自己的 Payload。
- **IP**：尽力而为、无状态、逐跳目的转发；地址靠 CIDR/掩码划分，同网 ARP，跨网走网关+NAT。
- **基本架构原则**：分组交换（简单+高效）、分层、封装可递归、最长前缀匹配。
