一个从未使用过系统的员工通过太湖登录时，不需要提前存在于 `user` 表，也不需要 `tof_access_rules`。

## 首次登录验证流程

1. 太湖网关完成员工登录，向请求注入：

```text
x-tai-identity  加密身份
timestamp
signature
x-rio-seq
```

2. Paperclip 使用太湖应用 Token 验证签名：

```text
SHA256(timestamp + token + 扩展头 + timestamp)
```

3. 使用同一个 32 字节 Token 解密 `x-tai-identity`：

```text
JWE / AES-256-GCM
```

得到：

```json
{
  "StaffId": 123456,
  "LoginName": "newuser"
}
```

4. 标准化 RTX 并生成稳定 ID：

```text
newuser → tof:newuser
```

5. 查询权限级别：

```text
硬编码超级管理员 → admin
tof_access_rules 有记录 → 使用记录中的级别
没有记录 → member
```

6. 首次向 `user` 表写入：

```text
id    = tof:newuser
name  = newuser
email = newuser@tencent.com
```

7. 普通 `member` 获得所有公司的隐式 `viewer` 权限：

- 可以只读浏览。
- 不能创建公司。
- 不写入 `company_memberships`。
- 不创建 Better Auth `session/account`。

应用侧当前验证了签名和 JWE 解密，但没有额外检查解密结果中的 `Expiration`，也没有校验 `timestamp` 的时间窗口；登录有效性主要依赖太湖网关。

## 如果给他管理员权限

已有管理员在管理页面添加：

```text
rtx   = newuser
level = admin
```

系统立即执行两项操作：

1. 写入 `tof_access_rules`：

```text
newuser | admin
```

2. 写入 `instance_user_roles`：

```text
tof:newuser | instance_admin
```

下一次请求重新解析身份时：

```text
TOF → tof:newuser
→ 命中 admin 规则
→ isInstanceAdmin = true
→ 获得全部公司的全局管理员权限
```

不需要重新创建用户，也不需要 Better Auth 登录。

管理员也可以在这个人首次登录前预先添加规则。此时权限记录先按 `tof:newuser` 创建，首次登录再创建 `user` 行。

删除该规则后，系统会删除 `instance_admin`，用户立即降回默认 `member/viewer`。
