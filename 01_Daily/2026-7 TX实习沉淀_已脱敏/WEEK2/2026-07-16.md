## 容器里的Agent，里面到底有什么

agent tree:

```
mirrors.tencent.com/tencentos/tencentos4(公司内部 OS 基座)
└── agent-base                              通用底座
    ├── agent-backend                       + 微信支付后端通用工具链
    │   ├── agent-paycode                   + 付款码业务仓
    │   ├── agent-c2cpay-dev                + C2C 社交支付业务仓
    │   ├── agent-realname-dev              + 实名认证业务仓
    │   ├── agent-paymethod-dev             + 用户支付方式业务仓
    │   ├── agent-receipt                   + 交易凭证业务仓
    │   ├── agent-liteappdevops             + LiteApp 运营系统业务仓 + 9 个平台 MCP
    │   └── agent-uat                       + UAT 真机调试工具链(adb/wdb)
    ├── agent-ceo                           + 招聘协调技能(SKILLS_KEEP收窄)
    ├── agent-wxpayclient-analysis          + 客户端源码运行期浅 clone + 分析类技能
    ├── agent-liteapp                       + 前端(Node)编译自检
    └── agent-e2etest                       + airdf e2e 测试机床 + adb/wdb
        └── agent-wxpayclient               + Android 编译工具链(JDK17+SDK/NDK)
```


env注入链路：
```
paperclip agent 配置(业务身份)
  → wxp_cloud adapter 编码成 REPO_URL/WXP_BUSINESS_REPOS/WXP_DESIRED_SKILLS 等
  → agent-cloud-api 塞进 Nomad dispatch 的 meta
  → Nomad HCL 的 env{} 块把 meta 映射成容器进程 env
  → entrypoint.sh(拉通用 skills) + airdf-node serve 的 prepareAssets()(拉这次专属的业务代码/skill 子集)
      读 env → git clone/cp 到 /workspace/{business,skills}/
  → 此刻镜像才第一次"沾上"业务，而镜像文件本身从头到尾没变过一个字节
```

1. agent-base 
	- image：必要工具链/环境+workspace骨架
	- run时：通过脚本注入skills
	- 继承树里的根结点，其他的在他基础上加各种业务仓/工具链/skills/mcp
2. airdf-node 
	- 常驻在每个容器里
	- 本身不干活，作为协议层/调度层
	- 干活spawn一个 agent cli出来
